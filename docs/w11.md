# 11주차 포트폴리오 5칸 — AI 챗봇 상태와 움직임

| 칸 | 내용 |
|---|---|
| **1. 무엇을 만들었나** | 채팅 UI(말풍선 2종 · 입력창 · 빈 상태 · 키보드 대응)와 오류·재시도(401/429/500/timeout → 오류 말풍선 + 다시 시도, 429 백오프 1s → 2s). |
| **2. 상태** | `idle`(입력 가능) → `sending`(입력·전송 잠금) → `typing`(점 3개) → `done`(AI 말풍선 + 맨 아래 스크롤) / `error`(오류 말풍선, 입력은 다시 가능). 화면은 `_sending · _typing · _error` 세 값으로만 결정된다. |
| **3. 움직임과 근거** | 점 3개는 점당 200ms: 1초를 넘는 대기에서 "멈췄다"가 아니라 "생각 중"을 알린다(Nielsen 1초 한계). 상태 전환은 AnimatedSwitcher 200ms, 스크롤 200ms: 0.1초보다 길어 변화가 인지되고 400ms보다 짧아 기다림을 늘리지 않는다. 전환은 한 번에 하나만 일어난다. |
| **4. 오류와 접근성** | 401 "키/권한" · 429 "잠시 후" · 500 "응답 없음" · timeout 30초 "네트워크" 문구가 화면에 남고 `다시 시도`는 마지막 메시지만 다시 보낸다. Reduce Motion(`disableAnimations`)이면 전환 0ms, 점은 멈춘 채 셋 다 켜서 정보는 유지한다(WCAG 2.3.3). 오류 문구는 `liveRegion`으로 화면 낭독기에 알린다. |
| **5. 이 움직임이 없으면 잃는 것** | 점 3개가 없으면 사용자는 앱이 죽었는지 모른다(상태의 가시성). 오류 말풍선이 없으면 실패가 조용히 사라져 같은 질문을 다시 입력해야 한다. 비활성 전송 버튼이 없으면 연타로 같은 요청이 여러 번 나간다. |
